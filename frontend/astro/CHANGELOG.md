## 1.1.0 — 2026-11-22

The second (or only) frontend at any directory ([ADR 0015](../../docs/adr/0015-several-frontends-by-directory.md),
[ADR 0016](../../docs/adr/0016-one-worker-with-static-assets.md) W3). With one frontend nothing
changes except the lines below that name the port or the directory.

- Nothing assumes `frontend/`, port 4321 or being the only frontend: the dev server and `astro
  preview` listen on the package's own port (`__PORT__`, the next free one for a second frontend).
- Beside several frontends, the dev proxy of `/api` sends this frontend's own local host
  (`<dir>.localhost:<api port>`) as the `Host` header, so `/api/admin/*`, which the Worker answers on
  the `admin` frontend's host alone, is reachable from `admin`'s dev server.
- Beside several frontends, the e2e run starts the API's chain with `start --only <dir>`, waits on
  `http://127.0.0.1:<api port>/api/health` and opens `http://<dir>.localhost:<api port>`; the
  `request` fixture (`tests/e2e/support.ts`) goes to 127.0.0.1 with the page's host as the `Host`
  header, because Node does not resolve `*.localhost` on Windows.
- Tests: `astro-config.test.ts` (port and proxy), the Playwright config for both variants; cases
  `two` (`site` and `admin`, islands on `admin`) and `one-at-site`.

## 1.0.0 — 2026-11-17

First release ([ADR 0014](../../docs/adr/0014-astro-cloudflare-pages.md)): the Astro frontend of the `astro-cloudflare` stack, usable alone.

- Astro 7 static output (`build.format: 'file'`, no adapter), `security.csp` (a hashed `<meta>` policy on every page with `default-src 'self'` and the other fetch directives, no `'unsafe-inline'`), a skip link and one `main` as the shell, an index page of one `h1` and a 404 page; no accounts, no example screen.
- `pages/`, `layouts/`, `components/ui/` (button, field, input, card, alert, spinner, skeleton, toast, theme toggle) on co-located SCSS over the layered global token tree (OKLCH brand tokens, light and dark, density), `services/validation.ts` (the zod facade), `models/<entity>/`, `nav.ts`, `public/theme-init.js`.
- With a server (`contract: { consumes }`): the client, SDK and zod schemas generated by Hey API into `src/services/generated/`, `services/api.ts` (the one wrapper: the envelope becomes an `ApiError` with its request id), the copy table of every envelope code and the form helper for field errors, the `/api` dev proxy. Alone, none of it and no `contract` command (ADR 0011).
- Lint: the layer map as zones, a control only in the kit, `zod` only in its facade, the generated runtime only in `services/`, no `fetch`, no `import.meta.env` outside `src/env.ts`, no inline handler or style attribute; proved by `tests/unit/eslint-boundaries.test.ts`.
- Vitest (the layout and every kit component through Astro's container, the services against a stubbed `fetch`, the styles tree, the boundaries, a real `astro build`) and Playwright on `phone` and `desktop` (shell, screens with axe and no policy violation, smoke), served by `astro preview` alone and by `serverless/cloudflare`'s `start` in the stack.
- `AGENTS.md`: the layer map, where each addition goes, `Adding a feature`, `Adding a content page` (a content collection, endpoints for generated text files, redirects and headers) and `Migrating a site into Astro` (pass-through first, the policy inventory, one page family at a time).
- Flag `islands` (off): `@astrojs/react` and the `src/components/islands/` convention; no island ships.
