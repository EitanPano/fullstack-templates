# Changelog

## 4.0.0 — 2026-11-12

The owner's folder rules ([ADR 0012](../../docs/adr/0012-next-spa-tree-colocated-scss.md)): `models/` holds one folder per noun with four file names, one folder is named `components`, and a component of two or more files is a folder. Markup, class names, copy, routes, URLs and behaviour are unchanged. A project generated from 3.x keeps its tree; there is no migration tool.

### Breaking

All paths are under `src/`.

| What | Before | Now, and what a project generated before does |
| --- | --- | --- |
| App chrome | `components/app-*.{vue,scss,spec.ts}`, `components/rtl.spec.ts` | `layout/app-*/app-*.{vue,scss,spec.ts}` (a folder per component), `layout/rtl.spec.ts`. The lint element `components` is now `layout`, and its messages say so. |
| Page screens | `pages/<module>/<name>-page.{vue,scss,spec.ts}` | `pages/<module>/<name>-page/<name>-page.{vue,scss,spec.ts}`; the `*.routes.ts` lazy imports and the lint's page patterns follow. | Shared components | `shared/components/<name>.{vue,scss,spec.ts}` | `shared/components/<name>/<name>.{vue,scss,spec.ts}`; imports name the file (`@/shared/components/base-button/base-button.vue`). |

## 3.1.0 — 2026-11-11

A frontend generated without a server ([ADR 0011](../../docs/adr/0011-frontend-without-a-server.md)) carries nothing that reaches one. A stack's output is unchanged, byte for byte.

### Added

- `alone-lean` case: the frontend alone with `i18n` and `pwa` off. The `alone` case now runs its e2e.

### Changed

- Gated on `server` (`onlyWhen.server` and bare `@server` markers; absent without a server): `openapi-ts.config.ts`, `src/services/generated/`, `core/config/api-client.*`, `core/interceptors/{error,http.provider,loading}.interceptor.*`, `models/api/`, `store/request-status.*`, `store/loading.store.*`, `shared/validators/server-errors.*`, `testing/stub-api.*`; the `api:types` script and the `@hey-api/openapi-ts` package; `installInterceptors` in `app/plugins.ts`; the dev and preview proxy in `vite.config.ts` and the service worker's `/api` rules (`navigateFallbackDenylist`, the runtime-cache note); nginx's `/api` upstream and resolver; the Playwright config's API web server; the API sentences of `.env.example`, `env.ts` and `AGENTS.md`.
- Gated specs, each with its successor: `smoke.spec.ts` › "the API answers on the page origin" (`GET /api/health`) is gated; the index route's `h1` and axe test stays and is the lone frontend's smoke. `plugins.spec.ts` › "registers the error interceptor on the generated client" and `zod-form.spec.ts` › "writes a server field error by path" are gated with the code they test. `shell.spec.ts` and `screens.spec.ts` run unchanged.
- `en.json` keeps its `errors.*` copy keys: JSON takes no markers, `he.json` must match them, and `zod-form` and the stores that arrive with a server read them.
- Kept in a lone frontend, because they take no markers or are one policy for both outputs: `eslint.config.mjs` and `tests/unit/eslint-boundaries.spec.ts` (the layer fences, so a server added later arrives inside them), `.prettierignore` and `tsconfig.node.json`.
- `AGENTS.md` (`@server` markers; a short no-server text where a reader needs one): gated are the generated-runtime and fetch-wrapper rules, the data steps of `Adding a feature` (contract, service, store, page, route, specs; a no-server recipe replaces them), the guarding and session-hint paragraphs, the form recipe, the `Errors` body, the stub and the two-mode e2e bullets, the `smoke.spec` sentence, and the Deployment lines for the dev proxy, `/api` routing, the service worker's `/api` rules, the deploy modes, nginx's `/api` upstream, Compose, `TRUST_PROXY`, cookies and body size. A list under `Adding a feature` names what arrives with a server and says the harness adds it (`scripts/scaffold.mjs`). The layer map keeps naming the data layer.

## 2.0.0 — 2026-11-09

([ADR 0009](../../docs/adr/0009-pages-components-colocated-styles.md)). A breaking move: the
routed pages sit flat in `pages/<module>/`, the app-wide components in `components/` with the
`app-` prefix, the primitives are `Base*`, and every stylesheet sits beside the page or component
that owns it, on a global token tree in `src/styles/`. No behaviour changes except the addition
below. A project generated from 1.x does not upgrade in place: the tables are the migration.

The styles rule changed with the move: a page or component that needs rules owns a sibling `.scss`
with its stem and references it with an empty `<style lang="scss" src="./<stem>.scss"></style>` block,
the last block of the file; a partial two components share is referenced by each of them. `scoped`
and a `<style>` body are refused. `src/styles/` is exactly `styles.scss`, `setup/`, `themes/` and
`basics/`, in cascade layers (`@layer setup, themes, basics;`); the sibling sheets are never layered,
so a page or component wins over the global tree at any specificity. `.icon` stays in
`shared/components/base-icon.scss`.

### Added

- The offline badge in the header enters and leaves through `<Transition name="status">`, with a
  `prefers-reduced-motion` rule that switches the motion off. The toast list stays on Reka's own
  `data-state` motion: Reka portals each toast into its viewport, so a `<TransitionGroup>` on the
  list would wrap a Teleport and animate nothing.
- `tests/unit/styles-tree.spec.ts` scans for stylesheet owners: `src/styles/` is exactly four
  entries; every sheet outside it has a sibling `.vue` with its stem whose `<style lang="scss" src>`
  block is empty and last, or two sibling referencers; no `scoped`, no `<style>` body, no `style`
  attribute; `.vue` files directly in `components/` start with `app-` and none in
  `shared/components/` does; the global partials sit in their `@layer` and no sibling sheet does.
  Each rule has a seeded negative case.

### Changed

- The boundaries lint reads the new tree: the element types are `components` (`src/components`)
  and `page` (`src/pages/<module>`), a page module never imports another, every message names
  `components/`, `pages/` or "a page". `vue/block-lang` pins `lang="scss"` on a `<style>` block
  (the empty `src` block passes) and `vue/no-restricted-block` for `style` is gone.
  `vue/no-restricted-html-elements` points to the `Base` wrapper.
- `density.spec.ts` and `rtl-styles.spec.ts` compile and scan `styles.scss` plus every `.scss`
  outside `styles/`.
- `template.yaml`: the `server:auth`, `i18n` and `pwa` lists name the new paths and carry the
  moved sheets.
